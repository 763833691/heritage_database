# 数据字典

## 1. 编码与枚举

### 1.1 公园类型 `park_type`

| 编码 | 含义 |
|------|------|
| `城市型` | 位于城市建成区或核心城区的遗址公园 |
| `城郊型` | 位于城市外围或近郊区域的遗址公园 |
| `乡村型` | 位于乡村或相对独立区域的遗址公园 |

### 1.2 批次 `batch`

| 编码 | 含义 |
|------|------|
| `1` | 第一批 |
| `2` | 第二批 |
| `3` | 第三批 |
| `4` | 第四批 |
| `5` | 第五批 |

### 1.3 评分等级 `grade`

| 等级 | 得分范围 | 标准化分值 |
|------|----------|----------|
| 好 | 80-100 | 100 |
| 较好 | 60-79 | 80 |
| 一般 | 40-59 | 60 |
| 较差 | 20-39 | 40 |
| 差 | <20 | 20 |

### 1.4 维度编码

| 编码 | 含义 |
|------|------|
| `B1` | 遗址保护效能 |
| `B2` | 文化传播效能 |
| `B3` | 教育传承效能 |
| `B4` | 文化活化效能 |

### 1.5 题项量表 `answer_value`

| 编码 | 含义 |
|------|------|
| `1` | 非常不同意 / 非常差 |
| `2` | 不同意 / 差 |
| `3` | 一般 |
| `4` | 同意 / 好 |
| `5` | 非常同意 / 非常好 |

### 1.6 情感标签 `sentiment_label`

| 编码 | 含义 | 得分范围 |
|------|------|----------|
| `POS` | 正面 | 0.3 ~ 1.0 |
| `NEU` | 中性 | -0.3 ~ 0.3 |
| `NEG` | 负面 | -1.0 ~ -0.3 |

### 1.7 用户角色 `role`

| 编码 | 含义 |
|------|------|
| `admin` | 管理员 |
| `researcher` | 研究者 |
| `guest` | 访客 |

### 1.8 数据来源标记

| 编码 | 含义 |
|------|------|
| `FIELD` | 实地调研 |
| `SURVEY` | 问卷调查 |
| `DOC` | 文献档案 |
| `GIS` | 空间数据 |
| `WEB` | 网络数据 |
| `GOV` | 政府公开数据 |

## 3. 校验规则

### 3.1 基础完整性

- `parks.name`、`parks.park_type`、`parks.province`、`parks.city` 不应为空
- `sites.park_id`、`sites.site_name` 不应为空
- `scores.park_id`、`scores.indicator_id`、`scores.normalized_score` 应保持一致
- `survey_answers.question_code` 不应为空

### 3.2 取值范围

- `normalized_score` 建议使用 `20 / 40 / 60 / 80 / 100`
- `answer_value` 取值建议为 `1 - 5`
- `world_heritage` 取值为 `0 / 1`
- `sentiment_score` 建议落在 `-1.0 ~ 1.0`

### 3.3 时间与坐标

- 日期字段建议统一为 `YYYY-MM-DD`
- 经纬度建议使用 WGS84
- 坐标字段在当前仓库中可用文本或 JSON 保存，后续如做空间分析可进一步拆分

## 4. 说明

- 本字典与当前 ORM 模型保持一致
- 如果后续字段新增或改名，应优先同步模型，再同步字典
- `protection_zones`、`managements`、`visitors` 目前仅作为扩展预留，不作为当前主表维护
