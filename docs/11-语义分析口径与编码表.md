# 轨迹语义分析口径与编码表

> 版本：v1.0 · 2026-09-20
> 适用范围：国家考古遗址公园田野调研 KML 轨迹照片的保护展示语义编码、空间指标计算与跨公园比较。
> 口径来源：课题组隋唐洛阳城试点已验证流程（`分析脚本.py` / `语义类型编码结果.csv`）。
> 实现文件：`backend/app/services/semantic_analysis.py`（编码表 `CODEBOOK` 与本文档逐字一致，改口径须同步本文档）。

本文件是论文「研究方法」章节的直接素材：编码表、优先级、聚类参数、指标定义与数据映射均可直接引用。

## 1. 语义编码表（A–F，未命中归 G）

每张照片归入且仅归入一个类型。归类按 **D ＞ E ＞ A ＞ C ＞ B ＞ F** 的优先级，自上而下取**首个命中**的关键词所属类型；全部未命中归 **G 其他**。数字互动（D）与运营消费（E）证据稀缺性最高，故优先级最高，优先保留。

| 编码 | 类型名 | 定义 | 关键词（命中任一即归入本类） |
|---|---|---|---|
| **D** | 数字互动展示 | 数字技术、互动装置与虚拟展示内容 | 互动触摸屏、电子展示屏、AI绘画、VR、数字展陈、问答、互动屏、AR、全息、数字 |
| **E** | 运营与消费场景 | 售票、文创、演艺、餐饮等运营与消费场景 | 票价、售票、文创、演艺、舞台、节目单、售卖机、消费、争霸赛、入口场景、商店、收银、游客中心、演出、门票 |
| **A** | 遗址本体展示 | 遗址本体、考古遗迹与出土物的原状展示 | 夯土、墩台、砖铺、柱础、柱坑、遗址层、车辙、蹄印、遗存、遗址本体、门道、发掘、出土、墓冢、封土、城墙遗址、基址、剖面、陶片、瓦当 |
| **C** | 阐释解说设施 | 展板、沙盘、标识、展厅等阐释与解说载体 | 展板、沙盘、说明牌、介绍牌、模型、浮雕、壁画、标识墙、主题墙、分布图、布局图、路线图、疆域图、剖面图、形制、展厅、展陈、展品、陈列、讲解员、导览、解说、博物馆 |
| **B** | 复原建筑与覆罩 | 复原/仿古建筑、保护棚罩及其外观 | 城楼、阙楼、金殿、天堂、穹顶、大棚、覆罩、斗栱、檐部、木塔、高塔、复原建筑、外观、对景、回望、复原、仿唐、仿古、保护棚、保护罩 |
| **F** | 景观环境与城市关系 | 广场、步道、绿化、城市与遗址的空间关系 | 天街、广场、俯瞰、远眺、绿化、城市、立交、草坪、城区、天际线、通廊、步道、里坊绿地、停车场、道路、农田、村庄、景观、水面、湿地 |
| **G** | 其他 | 未命中上述任一关键词 | —（兜底类型） |

### 1.1 归类规则细则

1. **唯一类型**：每张照片只产出一个编码，不存在多标签。
2. **优先级**：严格按 `D → E → A → C → B → F → G` 检测，首个命中的关键词决定类型。例如文本「复原建筑内的互动触摸屏」同时含 B（复原建筑）与 D（互动触摸屏），因 D 优先，归 **D**。
3. **分类输入文本**：由 `photo_text()` 拼合照片的 `description`（多模态语义描述）、`caption`（图注）、`poi`（附近 POI）、`address`（语义地址）、`file_name`（原始文件名），以 `；` 连接。多模态模型的描述只是分类的**输入文本**，分类本身由可复算的规则完成，不调用 LLM。

> 照片语义描述由模型路由 `vision.describe` 指定的**图像理解模型**生成（配置见 `backend/.env` 的 `MODEL_REGISTRY` / `MODEL_ROUTES`）。若该模型不支持图像输入，描述会退化为占位句，编码将大量落入 G 类；因此先用图像可用模型补全描述，再执行语义分析。
4. **关键词只增不改**：为保证与课题组已产出数据口径一致，既有关键词不得删除或修改；新增关键词须同步更新本文档与 `CODEBOOK`。

## 2. 点位簇切分

按拍摄顺序（`shot_time` 升序，缺失时间排最后，再按 KML 内序号 `seq`）遍历照片：

- 当前照片与上一张的**拍摄时间差 ＞ 5 分钟**，**或** **空间距离 ＞ 150 米**时，切分为新簇；
- 否则并入当前簇。

空间距离用 Haversine 公式按 WGS84 地球半径 `6 371 000 m` 计算。

| 参数 | 取值 | 常量 |
|---|---|---|
| 时间间隔阈值 | 5 分钟 | `CLUSTER_GAP_MINUTES = 5.0` |
| 空间间距阈值 | 150 米 | `CLUSTER_GAP_METERS = 150.0` |

## 3. 指标定义

| 指标 | 定义 | 计算口径 |
|---|---|---|
| 类型构成比 composition | 各语义类型照片数与占比 | `count / 照片总数 × 100%`，保留 1 位小数 |
| 拍摄密度 photo_density_per_km | 单位轨迹里程的照片数 | `照片数 / 轨迹里程(km)`，轨迹里程为 0 时返回 `null` |
| 点位簇 clusters | 切分后的簇数量与规模 | 见第 2 节；每簇记录照片数、首末时间、簇中心经纬度 |
| 分簇停留时长 stay_minutes | 簇内首末照片时间差 | `max(shot_time) − min(shot_time)`，单位分钟；簇内不足 2 个有效时间记 0 |
| 考察时长 duration_minutes | 轨迹起止时间差 | `track.end_time − track.start_time`，单位分钟 |
| 动线时空序列 spacetime | 前端散点图数据 | 每张有拍摄时间的照片：`t_min`＝相对首张照片的分钟数，`lat`＝纬度，`type`＝编码 |

照片总数、轨迹里程（km）、簇数由同一分析结果直接给出，跨公园比较时口径一致可直接对比。

## 4. 结果存储

- 分析结果落盘为 JSON：`backend/data/tracks/{track_id}/analysis.json`，UTF-8、缩进 1。
- **不新增数据库表或字段**，不改动现有 `track_file` / `track_photo` 结构。
- `POST /analyze` 与首次 `GET /analysis`（有照片时）会写入该文件；`GET /analysis` 优先返回已持久化结果，缺失则即时计算但不写盘。
- 结果含 `generated_at` 与 `codebook_version`，便于复算比对。

### 5.2 读取分析结果

```
GET /api/track/{track_id}/analysis
```

已有持久化结果时直接返回；否则即时计算（不写盘）。无照片时返回 `400`。

### 5.3 导出编码 CSV

```
GET /api/track/{track_id}/analysis.csv
```

返回 UTF-8 BOM 的 CSV，Excel 可直接打开。表头与行：

```
照片ID,序号,文件名,拍摄时间,语义类型编码,语义类型,点位簇,图注
```

行数 = 照片数 + 1（表头）。

### 5.4 跨轨迹（跨公园）比较

```
GET /api/track/analysis/compare?ids=12,15,18
```

`ids` 为逗号分隔的轨迹 ID。已持久化则读缓存，缺失则即时计算。响应（200）示例：

```json
{
  "codebook_version": "v1",
  "type_names": {
    "A": "遗址本体展示", "B": "复原建筑与覆罩", "C": "阐释解说设施",
    "D": "数字互动展示", "E": "运营与消费场景", "F": "景观环境与城市关系", "G": "其他"
  },

    {
      "track_id": 12,
      "name": "隋唐洛阳城国家考古遗址公园",
```

## 6. 前端图表数据映射

前端语义分析面板位于「田野调研 → 调研工作台 → 语义分析」步骤，全部用 ECharts 渲染，不新增依赖。

| 图表/组件 | 数据源字段 | 编码 |
|---|---|---|
| 指标卡 | `photo_count` / `distance_km` / `photo_density_per_km` / `duration_minutes` / `clusters.length` | — |
| 图 1 语义类型构成（横向条形图） | `composition` | x=照片数，y=「编码 + 类型名」；条端标注 `count（percent%）`；主色 `#085399` |

## 7. 复算与一致性

- 编码为纯规则函数 `classify_text(text)`，同一输入必得同一输出，无随机性，可离线复算。
- 分析输入为数据库中已持久化的照片语义字段，重跑 `POST /analyze` 会以最新数据覆盖 `analysis.json`。
- 修改编码表关键词、聚类阈值或指标口径时，必须同步修改 `backend/app/services/semantic_analysis.py` 与本文档，并在课题组数据上回归验证后再启用。
