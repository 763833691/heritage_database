# 调研报告自动导入功能设计方案

## 1. 背景与目标

项目已有 `20260529第三章.docx`（论文章节，含9个公园的D1-D27评分数据）和 `26-0503调研报告.doc`（调研报告），目前数据只能通过 Excel 模板手动导入或 `init_db.py` 硬编码插入。

目标：用户上传 `.docx` / `.doc` 调研报告 → 系统自动解析 → 提取公园、评分、指标等结构化数据 → 预览确认 → 一键入库。

## 2. 现有基础设施

| 能力 | 状态 |
|------|------|
| `python-docx==1.1.0` | ✅ 已安装 |
| LLM API（DashScope `qwen3.6-plus`） | ✅ 已打通 |
| Excel 批量导入 API | ✅ `POST /api/admin/import/*` |
| 数据模型（Park/Score/Indicator/Site/Survey） | ✅ 完整 |
| 文件上传 | ✅ FastAPI `UploadFile` |

## 3. 技术方案

### 3.1 整体流程

```
用户上传 .docx
  → 后端用 python-docx 提取纯文本
  → 调用 LLM 解析文本，提取结构化 JSON
  → 返回解析结果给前端预览
  → 用户确认后，调用已有 Excel 导入逻辑入库
```

### 3.2 为什么用 LLM 而不是规则解析

调研报告是**半结构化中文文本**，格式不统一：
- 第三章：论文风格，评分数据散落在段落中（如"圆明园得分 73.47 分""D1 遗址本体完整性得分 60 分"）
- 调研报告：表格+段落混合

传统正则表达式需要针对每种报告格式写规则，维护成本高。LLM 天然擅长从非结构化文本中提取实体和数值，且项目已接入 DashScope。

### 3.3 LLM 解析 Prompt 设计

将整个文档文本作为上下文，要求 LLM 返回结构化 JSON：

```json
{
  "parks": [
    {
      "name": "圆明园国家考古遗址公园",
      "park_type": "城市型",
      "province": "北京",
      "scores": [
        {"code": "D1", "name": "遗址本体完整性", "score": 60, "dimension": "遗址保护效能"},
        {"code": "D2", "name": "遗址本体安全性", "score": 60, "dimension": "遗址保护效能"}
      ],
      "description": "..."
    }
  ],
  "indicators": [
    {"code": "D1", "name": "遗址本体完整性", "dimension": "遗址保护效能"}
  ],
  "survey_summary": {
    "park": "圆明园",
    "total_distributed": 109,
    "total_collected": 109,
    "valid_count": 109
  }
}
```

### 3.4 分步处理策略

文档可能很长（第三章 2.6MB 文本），一次性发给 LLM 可能超 token 限制。采用分步策略：

1. **第一步：拆分** — python-docx 按段落读取，按章节标题（"第三节""第X节"）切分
2. **第二步：逐段解析** — 每个段落在 2000-4000 字左右，LLM 分别解析
3. **第三步：合并去重** — 合并所有段落的解析结果，同名公园的评分合并

### 3.5 容错设计

- LLM 解析失败时，标记该段落为"需人工处理"
- 解析出的公园名与数据库中已有公园做模糊匹配
- 前端预览页显示"匹配成功""待确认""匹配失败"三种状态
- 用户可手动修正后再确认入库

## 4. 需要新增/修改的文件

### 新增文件（3个）

| 文件 | 作用 |
|------|------|

## 5. API 设计

### POST /api/admin/upload/report

```
请求：multipart/form-data { file: .docx }
响应：{
  "file_name": "第三章.docx",
  "sections": 12,
  "parsed_data": {
    "parks": [{ name, park_type, scores: [...], confidence: 0.9 }],
    "indicators": [...],
    "surveys": [...]
  },
  "warnings": ["第3段无法解析", "XX公园未匹配到数据库"]
}
```

### POST /api/admin/upload/report/confirm

```
请求：{ "parks": [...], "scores": [...], ... }
响应：{ "imported": { "parks": 3, "scores": 81 } }
```

## 8. 关键决策

- **复用 LLM**：已有 DashScope 配置，无需新增依赖或付费
- **不修改现有导入逻辑**：确认导入时调用已有 `import_scores` 等函数
- **分步解析**：长文档自动切段，每段独立调 LLM
- **人工确认**：解析结果必须经用户预览确认后才入库，避免脏数据
- **不影响现有功能**：纯增量功能，不改动已有 API
