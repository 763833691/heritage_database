# 田野调研语义化与调研报告自动生成 · 整体工作流方案

> 版本：v1.0 · 2026-09-17 · 状态：待评审
> 前置文档：[07-两步路KML照片提取方案](07-两步路KML照片提取方案.md)（本文档的第 2 节即方案 07，不再重复展开）

## 1. 目标与范围

把一次田野调研的全部原始材料——**轨迹照片（KML）、录音文件、现场拍摄照片、PDF/文献资料**——统一接入平台，自动完成：

```
原始材料 → 语义化提取 → 时间线对齐 → 语义检索/知识图谱 → 调研报告（人工确认后）自动生成
```

最终产出：一篇带图、带数据、带引用的结构化调研报告（docx），且报告中每一张图、每一个结论都可追溯到原始材料。

## 2. 整体工作流（五阶段流水线）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 阶段① 采集接入        阶段② 语义化提取      阶段③ 对齐组织      阶段④ 检索图谱   阶段⑤ 报告生成 │
│                                                                          │
│ KML 轨迹文件 ──┐    坐标→逆地理地址 ──┐                         ┌─→ 报告大纲(人工确认)│
│ 录音 m4a/mp3 ──┼──▶ 录音→转写+要点 ────┼──▶ 统一「调研事件」时间线 ──▶ 语义检索/KG ──▶ LLM 分章撰写 │
│ 现场照片 ──────┤    照片→视觉语义描述 ─┤    (时间+地点+主题)              │  引用自动溯源      │
│ PDF/文献 ──────┘    文献→实体关系抽取 ─┘                         └─→ 图表自动配图 ────┘ │
└──────────────────────────────────────────────────────────────────────────┘
```

**核心设计：「调研事件」（SurveyEvent）是整条流水线的枢纽。** 一次调研 = 一个 `survey_task`，所有材料语义化后都转换成带 **时间戳 + 地理位置 + 主题标签** 的事件，挂到统一时间线上。报告生成时按时间线/主题检索事件，而不是零散地拼材料。

## 3. 四类材料的处理管道

### 3.1 KML 轨迹 + 轨迹照片（方案 07 已有，作为本工作流的采集入口之一）

- 解析轨迹点与照片点 → 下载原图 → 逆地理编码 → 每张照片生成语义描述。
- 产出：`track_file` / `track_photo` 两表 + 磁盘照片。
- 每张照片天然带**拍摄时间 + 坐标**，直接转为调研事件（类型：`photo`）。

### 3.2 录音文件 → 语音转写 → 要点抽取

复用现有 `app/kg/services/asr_service.py`（腾讯云录音文件识别极速版，已可用）：

1. 上传录音（m4a/mp3/wav/amr，按现有 `resolve_voice_format`）→ ASR 转写全文文本。
2. LLM（现有 `llm_provider`，qwen-plus）对转写文本做**要点抽取**：谁、在哪里、讲了什么、涉及哪个遗址点/主题、关键数字与评价。
3. 语义增强：
   - **时间对齐**：录音若无拍摄时间，用文件名时间 / 用户手填 / 取轨迹中最接近的轨迹点时间自动推断；
   - **地点对齐**：同上，匹配最近轨迹点坐标 → 逆地理地址。
4. 产出：录音文本 + 要点 + 时间/地点 → 调研事件（类型：`audio`）。

> 录音里往往有最有价值的调研口述（讲解员介绍、访谈），是报告「现状描述」章节的主力素材。

### 3.3 现场照片 → 视觉语义描述

手机现场拍的照片（非 KML 内）走另一条管道：

1. **EXIF 提取**：时间、GPS（多数手机拍照默认带坐标）。
2. **GPS 缺失时**：① 文件名时间匹配轨迹最近点借用坐标；② 用户在上传界面手动在地图上点选位置。
3. **视觉理解**：调多模态模型生成中文描述：画面内容、遗址要素（墓葬/城墙/展陈/标识牌/游客行为…）、可用于报告的一句话图注。**实现方式：不新增任何依赖，直接复用系统现有的 OpenAI 兼容视觉调用通道**（`kg/services/scanned_pdf_extractor.py` 中扫描件 OCR 已在用，`POST {base_url}/chat/completions` + `image_url` base64 格式）。将其抽出一个公共 `vision_client.describe_image(img_bytes, prompt)`，把 prompt 从"识别正文"换成"遗址调研照片语义描述+报告图注"即可。模型端点走配置（`openai_base_url` + `openai_vision_model` + key），**可无缝接豆包（火山方舟，OpenAI 兼容）、通义千问-vl 或任何兼容端点**，零代码切换。
4. 产出：照片 + 坐标 + 视觉描述 + 图注 → 调研事件（类型：`photo`）。

### 3.4 PDF / 文献资料 → 实体关系抽取

复用现有知识图谱子系统文件库（`/kg/vault`，PDF/CAJ/TXT 解析已可用）：

- 文献解析 → LLM 实体关系抽取（现有 `doc_parser.parse_with_llm`）→ 挂到知识图谱；
- 与调研事件通过**遗址点名称、地名**自动关联（如 KML 轨迹提到「海昏侯墓园」，文献中同名词条自动挂接），作为报告「背景与文献综述」章节素材。

## 4. 数据模型（在方案 07 两张表之外新增）

```text
survey_task                  一次调研任务（对应一篇报告）
  id, 标题, 遗址公园id, 调研日期, 状态, 创建人

survey_material              材料清单（统一登记四类原始材料）
  id, survey_task_id, 类型(kml/audio/photo/pdf), 原始文件名,
  存储路径, 处理状态, 处理进度, 错误信息

survey_event                 ★ 调研事件（语义化后的统一单元）
  id, survey_task_id, 事件类型(photo/audio/photo_desc/literature),
  时间戳, 纬度, 经度, 语义地址(省市区街道POI),
  标题(自动生成), 正文/描述, 来源material_id,
  主题标签[], 关联遗址点id, 可用于报告(bool)

survey_report                报告实例
  id, survey_task_id, 大纲(json,人工可改), 章节内容(json),
  docx路径, 状态(drafting/confirmed/exported), 版本
```

已有表复用：`track_file/track_photo`（方案 07）、`literature`（文献）、KG 的 `state.json/graph.json`。

## 5. 报告生成（阶段⑤）——可控、可溯源、可人工介入

分四步，避免「一键生成不可控大文章」：

1. **大纲生成**：LLM 读取该任务全部调研事件摘要 + 报告类型（调研报告/评估报告/简报），生成大纲（标准章节：概况→遗址本体→保护现状→展示利用→问题与建议…），**前端展示可人工增删改章节**。
2. **分章撰写**：逐章调用 LLM，输入 = 该章相关事件（按主题标签+时间检索）+ 关联文献要点 + 写作要求（学术口径、字数）；输出章节正文。
3. **自动配图与数据**：章节中自动插入对应时间/地点的照片（带图注，图注 = 拍摄时间+语义地址+视觉描述）；轨迹数据自动生成图表（海拔剖面、点位分布图，复用项目 ECharts/Leaflet 出静态图）。
4. **导出**：渲染为 docx（python-docx 已在依赖中），文末附「材料溯源表」（章节 → 引用的事件/照片/录音/文献清单）。人工在 Word 里做最终修改。

> 引用溯源原则：**报告里每一个事实性句子都要能点回原始材料**。LLM 输出时强制带 `event_id` 引用标记，渲染时转成尾注。

### 5.1 章节—数据源映射（对标《统万城国家考古遗址公园调研报告》42 页结构）

对标报告的章节骨架（摘要 / 一背景目的 / 二调研过程 / 三对象概况 / 四成效与问题研判 / 五对策建议 / 六结论 / 附录 / 参考文献），逐章映射到本平台数据源与自动化程度：

| 章节 | 数据源 | 自动化程度 |
|---|---|---|
| 摘要、六结论 | 全文生成 | 自动（最后生成） |
| 一、调研背景与目的 | 任务元数据 + 文献库要点（LLM 综述） | 自动 |
| 二、调研过程 | ★工作流数据独占：KML 轨迹（调研时间、踏勘路线、点位）、录音 ASR 转写（访谈实录）、照片清单 | **全自动**（这是其他工具替代不了的章节，轨迹+录音时间线直接成文） |
| 三、调研对象概况 | 公园基础档案（现有 `park/site/location` 表）+ 文献实体抽取 + 现场照片自动配图（图 X.X + 时间地点图注） | 半自动：文字自动、规划图纸类插图（如"功能分区图"）需人工插入并标注来源 |
| 四、成效与问题研判 | 调研事件（录音要点、照片视觉发现）+ 问卷/评论/评分数据（现有 `survey/review/score` 表） | 半自动：发现自动归纳，研判口径人工确认 |
| 五、对策建议 | LLM 基于第四章问题生成 | 自动起草，**必须人工把关**（对策是报告责任主体） |
| 附录 | 调研事件清单、访谈记录全文、照片索引表 | 自动 |
| 参考文献 | 文献库条目 + 引用格式（GB/T 7714） | 自动 |

经验比例：全自动章节约 40%，半自动约 40%，纯人工约 20%（规划图纸、需核实的统计数字）。这与统万城报告的产出方式一致——正文里"图 X.X（来源：《统万城遗址保护总体规划》）"这类引注本来就依赖人工标注来源，平台把它变成结构化字段即可。

### 5.2 报告模板与排版控制（格式工作台）

报告格式不硬编码，做成**「报告模板」配置对象**，一次配置多份报告复用。模板分四层：

**① 版式样式（docx 渲染层）**

| 配置项 | 说明 | 默认 |
|---|---|---|
| 页面 | A4、页边距、页眉页脚（报告题名/页码） | A4，上下 2.54cm 左右 3.17cm |
| 字体 | 正文（宋体/仿宋）、标题（黑体）、字号、行距、首行缩进 | 正文仿宋小四、1.5 倍行距、首行缩进 2 字符 |
| 标题层级 | 章/节/小节编号规则（"一、（一）、1.（1）"式中文层级） | 对齐统万城报告层级 |
| 封面 | 报告题名、副题（课题编号）、单位、日期，可开关 | 开 |
| 摘要/目录 | 自动生成目录（Word 域，可刷新页码） | 开 |

**② 图表规则（自动填写层）**

| 配置项 | 说明 | 默认 |
|---|---|---|
| 图编号规则 | 按章编号"图 3.1、图 3.2…"，全文自动连续编号 | 按章编号 |
| 图注格式 | 模板变量：`{编号}：{标题}（拍摄时间：{时间}，{语义地址}）` | 时间+地址双要素 |
| 表编号规则 | "表 3-1、表 3-2…" | 按章编号 |
| 表样式 | 三线表 / 全框线、表头加粗 | 三线表 |
| 图片来源标注 | 平台照片自动标"（来源：本次调研拍摄）"；人工上传的规划图等标注"（来源：{文献名}）" | 自动+人工可改 |
| 图片尺寸与上限 | 通栏/半栏、每章插图上限（防堆砌，超出进附录） | 通栏宽 14cm、每章 ≤ 8 图 |

**③ 图片插入策略（位置自动决策）**

- LLM 撰写章节时按语义打 `插入点标记`（如 `[IMG: 海昏侯墓园东门]`），渲染器按标记匹配事件库中同地点/同主题照片；
- 匹配不到时按**时间就近原则**取相邻事件照片，并在后台记录匹配依据（可溯源）；
- 每处插入点最多 1 张，多余照片按规则进附录「调研照片索引表」。

**④ 引用与附录规则**

- 正文引用标记 `[EV:12]` 渲染为尾注或括注；参考文献按 GB/T 7714 自动排列；
- 附录自动生成：A 调研事件清单、B 访谈录音转写全文索引、C 照片索引表（缩略图+图注）。

**格式工作台（前端页面）**：左侧模板配置表单（分组折叠，改即存为模板版本），右侧**实时预览**——用同一份事件数据渲染 HTML 预览稿（与 docx 版式近似），确认后一键导出 docx。支持「保存为新模板 / 从统万城样式复制」，让下一份报告零配置沿用。

## 6. 复用清单（现有代码直接复用，标★为本期主要工作量）

| 能力 | 现有模块 | 复用方式 |
|---|---|---|
| 语音转写 | `kg/services/asr_service.py`（腾讯云） | 直接调 `recognize()` |
| LLM 抽象 | `services/llm_provider.py`（DashScope/OpenAI/Mock） | 要点抽取、大纲与撰写 |
| ★ 多模态视觉调用 | `kg/services/scanned_pdf_extractor.py`（OpenAI 兼容 `/chat/completions` + image_url） | **抽出公共 `vision_client.describe_image()`，换 prompt 即用于照片语义描述；端点配豆包/千问-vl，零依赖** |
| 文献解析 | `services/doc_parser.py` + KG 文件库 | 直接复用 |
| 实体关系抽取 | `services/doc_parser.parse_with_llm` | 直接复用 |
| RAG 检索 | `services/rag_engine.py` + ChromaDB | 报告章节素材检索；**调研事件文本直接入现有 ChromaDB 集合，不新建向量库** |
| 知识库存储 | KG `state.json/graph.json` + 文件库 | **survey_event 作为图谱节点类型挂入现有 KG，不建平行知识库** |
| 图表 | 前端 ECharts / 后端 pandas | 轨迹图表、统计图 |
| Excel/docx | pandas/openpyxl/python-docx | 汇总导出、报告导出 |
| 异步任务/进度 | FastAPI BackgroundTasks + status 轮询 | 各管道统一进度协议 |
| ★ KML 解析管道 | 无（方案 07 新建） | M1 实现 |
| ★ 调研事件模型与时间线 | 无（新建） | MVP 实现 |
| ★ 报告生成器 | 无（新建，含大纲/分章/溯源渲染） | MVP 实现 |

> **不臃肿三原则**：① AI 能力全部下沉到现有三个 service（asr_service / llm_provider / vision_client），survey 模块只做编排；② 语义化结果统一存 `survey_event` 一张表，检索走现有 ChromaDB、图谱走现有 KG 存储，不建第二套知识库；③ PDF 文献管道完全不动，只在地名/遗址点名上和事件做关联。

## 7. 前端信息架构与交互逻辑

### 7.1 导航入口：新增一个一级 Tab「田野调研」

与「知识图谱（文件库/处理流程）」同级的顶级导航项，路由挂法与 KG 完全一致（`Layout.vue` 顶部菜单加一项 + `router/index.js` children 下注册）：

```text
顶部导航：首页 | 研究数据 | 遗址公园 | 地图浏览 | 对比分析 | 知识图谱 | 文件库 | 处理流程
        | 【田野调研】← 新增 | AI助手 | 知识库 | 文献计量

/survey                 → 调研任务列表（新建任务、历史任务卡片，显示处理状态）
/survey/:id/ingest      → 材料接入（该任务的四类上传入口 + 进度）
/survey/:id/timeline    → 时间线 + 地图双视图（事件校对）
/survey/:id/report      → 报告工作台（大纲/模板/预览/导出）
```

四个路由共用一个 `SurveyLayout`（左侧步骤条：① 材料接入 → ② 时间线校对 → ③ 报告生成），用户在任务内始终知道自己在哪一步、下一步是什么；`meta.wide = true` 与 KG 页面一致。

### 7.2 页面交互要点

1. **调研任务**（`/survey`）：任务列表/新建，一个任务聚合本次全部材料；卡片显示"照片 x 张 / 录音 x 段 / 事件 x 条 / 报告状态"。
2. **材料接入**（`/survey/:id/ingest`）：四个上传入口（KML / 录音 / 照片 / 文献），统一进度条（解析中 → 下载照片 x/57 → 语义提取 x/57），失败项单独重试，不打断其他项。
3. **时间线**（`/survey/:id/timeline`）：横向时间轴 + 地图双视图联动（点地图点定位时间轴位置）；每事件可编辑标题、主题标签、「可用于报告」开关——**这是全链路唯一强制人工环节，页面设计上把它做成"校对清单"，全部确认后才允许进入报告生成**。
4. **报告工作台**（`/survey/:id/report`）：大纲编辑 → 分章生成（每章独立"重新生成"按钮）→ 格式模板配置 + 实时预览（见 5.2）→ 导出 docx。

## 8. 实施路线（MVP 优先，轻量起步）

先跑通「最小闭环」再逐段加料，每一段都可独立验收。前期不要动 PDF 文献管道（它已成熟），也不要建前端大页面（复用现有 KG 风格组件快速拼）。

### MVP（约 6 人日，目标：刘贺主墓 KML 端到端出报告雏形）

| 步骤 | 内容 | 验收 |
|---|---|---|
| S1 | 抽 `vision_client` 公共模块 + KML 解析/照片下载/逆地理（方案 07 后端部分） | 57 张照片下载入库，每张有逆地理地址 |
| S2 | 照片视觉语义描述（调豆包/千问-vl，prompt：画面内容+遗址要素+报告图注） | 每张 photo 有中文描述与图注 |
| S3 | `survey_task` / `survey_event` 两表 + 事件生成 | 照片事件全部挂到时间线 |
| S4 | 报告生成器 v1：**只先生成第二章「调研过程」**（时间线直接成文 + 自动配图） | 导出 docx 章节，图文齐全、带来源表 |

### 增量 1（+3 人日）：录音管道

## 9. 成本估算（每次调研，57 张照片 + 3 小时录音 + 50 张现场照 + 5 篇 PDF 量级）

## 10. 验收标准（整体）

1. 一次调研的四类材料全部接入，自动处理成功率 ≥ 95%，失败项可定位可重试。
2. 时间线上照片、录音、文献事件时间/地点正确率抽样 ≥ 90%。
3. 报告生成：大纲可人工修改；单章可独立重生成；docx 内图文混排、图表齐全。
4. 溯源：报告正文每章末尾列出引用的事件/材料清单，点击可回看原始文件。
5. 全流程在 SQLite 本地模式跑通，不依赖 Neo4j（图谱增强为可选项）。
