# 遗产保护文献知识库设计方案

> 参考 Andrej Karpathy "LLM Wiki" 架构 + 文献计量法（Bibliometrics），结合项目现有技术栈

---

## 1. 设计哲学：Karpathy × 文献计量

### 1.1 核心思想

Karpathy 的 **"File Over App"** + 文献计量法的 **"数据驱动知识发现"**：

| 维度 | Karpathy 式知识库 | 文献计量法 |
|------|-------------------|-----------|
| 知识单元 | 单篇文献 → Markdown | 文献集合 → 统计规律 |
| 分析方式 | LLM 阅读理解 | 引文网络、共现矩阵 |
| 输出 | 摘要、概念页、交叉引用 | 研究热点、趋势、学术共同体 |
| 价值 | 深度理解每一篇 | 宏观把握整个领域 |
| 关系发现 | LLM 语义推理 | 引文耦合、共词分析 |

两者互补：
- **Karpathy** 告诉你"这篇文献说了什么"
- **文献计量** 告诉你"这篇文献在整个领域中的位置"

### 1.2 为什么需要文献计量

对于一个遗产保护论文/课题：

1. **文献综述自动化**：不是手动翻几十篇论文，而是系统自动告诉你研究脉络
2. **研究空白发现**：关键词演化 + 时间序列 → 哪些方向还没人做
3. **学术影响力评估**：哪些学者/机构是核心，引用网络如何
4. **答辩支撑**：用数据证明"我的选题填补了XX空白"

## 3. 文献计量核心指标

### 3.1 单篇文献元数据

LLM 从文献中提取的结构化信息：

```
{
  "title": "大遗址保护与利用研究",
  "authors": [{"name": "张三", "institution": "北京大学"}],
  "year": 2024,
  "journal": "文物保护与考古科学",
  "keywords": ["大遗址", "保护规划", "社区参与", "活化利用"],
  "abstract": "...",
  "citations": ["被引文献1", "被引文献2"],
  "funding": "国家社科基金(编号)",
  "language": "zh",
  "type": "期刊论文"  // or 学位论文/会议论文/政策报告/著作
}
```

### 3.2 文献计量指标

| 指标 | 计算方式 | 可视化 |
|------|---------|--------|
| 发文量趋势 | 按年份统计 | 折线图 |
| 关键词共现 | 两两关键词在同一文献中出现次数 | 共现矩阵热力图 |
| 引文网络 | 文献间引用关系 | 有向网络图 |
| 作者合作网络 | 合著关系 | 无向网络图 |
| 机构分布 | 按机构统计发文量 | 柱状图/地图 |
| 研究主题聚类 | 关键词+摘要向量聚类 | 散点图/主题河流图 |
| 高被引文献 | 被引次数 Top-N | 排行榜 |
| 突现词检测 | 某时段突然高频出现的关键词 | 突现词表 |
| 期刊分布 | 按期刊/来源统计 | 饼图 |

### 3.3 研究前沿识别

基于 Kleinberg 突现检测算法：

```
2019-2021: "遗址保护" "本体修复"      ← 传统热点
2021-2023: "数字化" "虚拟复原" "VR"   ← 技术驱动
2023-2025: "社区参与" "活化利用"       ← 人文转向
2025-   : "AI辅助" "知识图谱" ...      ← 新兴方向 (突现词！)
```

## 4. LLM 提示词设计（文献计量增强版）

### 4.1 文献结构化提取

```
你是文化遗产文献分析助手。请阅读以下文献，提取结构化信息。
特别注意：必须提取所有参考文献条目（作者、标题、年份）。

返回 JSON：
{
  "title": "完整标题",
  "authors": [{"name": "作者名", "institution": "机构"}],
  "year": 年份数字,
  "journal": "期刊/会议/出版社",
  "keywords": ["关键词1", "关键词2", ...],
  "abstract": "200字摘要",
  "type": "期刊论文|学位论文|会议论文|政策报告|著作",
  "funding": "基金信息",
  "methodology": "研究方法",
  "references": [
    {"author": "张三", "title": "被引文献标题", "year": 2020}
  ],
  "cites_parks": ["提到的遗址公园"],
  "core_argument": "一句话核心论点"
}
```

### 4.2 文献关系深度发现

```
新文献 A 已入库。请扫描知识库中所有已有文献，找出与 A 的关系：

1. 引用关系：A 引用了哪些已有文献？哪些已有文献引用了 A？
2. 主题关联：A 与哪些已有文献共享关键词/研究对象？
3. 观点关系：A 支持/挑战/补充了哪些已有文献的观点？
4. 方法论关系：A 与哪些文献使用了相同的研究方法？
5. 时间定位：A 在该领域研究时间线上处于什么位置？
   - 开拓性工作？验证性研究？综述？方法论创新？

返回：{"relations": [{"target": "文献ID", "type": "...", "strength": 0.8, "explanation": "..."}]}
```

### 4.3 领域综述自动生成

```
基于知识库中关于"大遗址保护"的 23 篇文献，请生成：

1. 研究脉络：按时间线梳理核心研究阶段
2. 核心学者与团队：谁在做什么
3. 方法论演进：研究方法如何变化
4. 共识与争议：学界一致同意什么？争论什么？
5. 研究空白：哪些问题还没被充分研究？
6. 关键文献推荐：每个阶段必读的 3-5 篇

请附带引用数据支持每个结论。
```

## 6. 数据模型

### 6.1 文献表 (新增)

```python
class Literature(Base):
    __tablename__ = "literature"

    id = Column(Integer, primary_key=True)
    title = Column(String(500), nullable=False)
    authors = Column(Text)  # JSON: [{"name":"...","institution":"..."}]
    year = Column(Integer, index=True)
    journal = Column(String(200))
    keywords = Column(Text)  # JSON: ["kw1","kw2"]
    abstract = Column(Text)
    doc_type = Column(String(20))  # 期刊论文/学位论文/...
    funding = Column(String(200))
    methodology = Column(Text)
    file_path = Column(String(500))  # knowledge_base/raw/...
    wiki_path = Column(String(500))  # knowledge_base/wiki/...
    raw_metadata = Column(Text)  # LLM 返回的完整 JSON
    vector_id = Column(String(100))  # ChromaDB 中的 ID
    created_at = Column(DateTime, server_default=func.now())
```

### 6.2 引文关系表

```python
class Citation(Base):
    __tablename__ = "citations"

    id = Column(Integer, primary_key=True)
    source_id = Column(Integer, ForeignKey("literature.id"))
    target_title = Column(String(500))
    target_author = Column(String(100))
    target_year = Column(Integer)
    # 如果 target 也在库中，填充 target_id
    target_id = Column(Integer, ForeignKey("literature.id"), nullable=True)
```

### 6.3 文献关系表

```python
class LitRelation(Base):
    __tablename__ = "lit_relations"

    id = Column(Integer, primary_key=True)
    source_id = Column(Integer, ForeignKey("literature.id"))
    target_id = Column(Integer, ForeignKey("literature.id"))
    relation_type = Column(String(30))  # cites/supports/contradicts/complements/shares_topic
    strength = Column(Float, default=0.5)
    explanation = Column(Text)
```

## 8. AI 助手知识库集成

扩展现有 `rag_engine.py` 和 `Chat.vue`：

- 搜索时同时查询数据库（公园评分）+ 知识库（文献）
- 答案分为"数据"和"文献依据"两部分
- 文献引用格式自动生成（GB/T 7714）

```
用户：遗址保护和活化利用之间怎么平衡？

AI 回答：

根据知识库中 15 篇相关文献的研究：

**学界共识**
1. 保护是底线，活化是延伸（张三，2024；李四，2023）
2. 社区参与是实现平衡的关键机制（王五，2022）

**争议点**
3. 商业开发的程度：适度（陈六，2024）vs 严格限制（赵七，2023）

**研究空白**
4. 缺乏量化评估活化对保护影响的实证研究

📊 相关文献计量：该主题 2019 年起热度持续上升，
   2024 年发文量同比增长 40%

📚 推荐阅读：
[1] 张三. 大遗址保护与利用研究[J]. 文物保护, 2024. (被引12次)
[2] 李四. 社区参与视角下的遗产活化[J]. 文化遗产, 2023.
```

## 11. 与论文答辩的直接关联

这个功能不仅是一个"文献管理工具"，更直接服务于论文写作：

| 论文需求 | 系统能力 |
|----------|----------|
| 文献综述 | LLM 自动生成某主题的研究综述 |
| 研究空白论证 | 计量分析 → "该方向 2022 年后发文量下降，AI 辅助方向刚起步" |
| 参考文献管理 | 自动提取引文、GB/T 7714 格式化 |
| 答辩 PPT 数据 | 一键导出"研究趋势图""关键词演进图" |
| 理论框架支撑 | 知识图谱展示你的研究在学术版图中的位置 |
