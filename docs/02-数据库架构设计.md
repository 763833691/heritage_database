# 数据库架构设计

## 1. 架构说明

当前仓库采用“关系数据库为主、图数据库为辅”的存储思路：

- 关系数据库负责保存调研业务的主数据
- Neo4j 负责知识图谱与实体关系查询
- ChromaDB 负责后续的向量检索扩展

代码层面支持 SQLite 与 PostgreSQL 两种关系库：

- `DB_TYPE=sqlite`：本地单机调试模式，默认写入 `backend/data/heritage.db`
- `DB_TYPE=postgres`：部署模式，Docker Compose 默认推荐

当前初始化方式以 ORM `Base.metadata.create_all()` 为主，尚未形成完整的迁移脚本流水线。

## 2. 核心实体关系

```text
parks 1 ── N sites
parks 1 ── 1 locations
parks 1 ── 1 exhibitions
parks 1 ── N scores
parks 1 ── N surveys
surveys 1 ── N survey_answers
parks 1 ── N reviews
parks 1 ── N education_activities
parks 1 ── N communities
scores N ── 1 indicators
users 独立认证实体
```

## 3. 表结构总览

| 表名 | 用途 | 关键关系 |
|------|------|----------|
| `parks` | 遗址公园基础档案 | 其他业务表的主表 |
| `sites` | 遗址点信息 | `park_id -> parks.id` |
| `locations` | 区位与城市环境信息 | `park_id -> parks.id`，一对一 |
| `exhibitions` | 展示利用与传播信息 | `park_id -> parks.id`，一对一 |
| `indicators` | 文化效能评价指标 | 被 `scores` 引用 |
| `scores` | 指标评分结果 | `park_id`、`indicator_id` 外键 |
| `surveys` | 问卷调查批次 | `park_id -> parks.id` |
| `survey_answers` | 问卷答案明细 | `survey_id -> surveys.id` |
| `reviews` | 网络评论数据 | `park_id -> parks.id` |
| `education_activities` | 教育活动记录 | `park_id -> parks.id` |
| `communities` | 社区共建与合作数据 | `park_id -> parks.id` |
| `users` | 系统账号与权限 | 登录认证使用 |

## 4. 主要表说明

### 4.1 `parks`

遗址公园主表，承载项目最核心的对象。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Integer | 主键 |
| `name` | String(100) | 公园全称 |
| `short_name` | String(50) | 简称 |
| `park_type` | String(20) | 城市型 / 城郊型 / 乡村型 |
| `batch` | Integer | 批次 |
| `province` | String(20) | 省份 |
| `city` | String(30) | 城市 |
| `district` | String(30) | 区县 |
| `address` | String(200) | 地址 |
| `longitude` / `latitude` | Float | WGS84 坐标 |
| `total_area` | Float | 总面积 |
| `core_area` | Float | 核心保护区面积 |
| `buffer_area` | Float | 缓冲区面积 |
| `protection_level` | String(100) | 保护级别 |
| `heritage_level` | String(100) | 遗产级别 |
| `world_heritage` | Integer | 是否世界遗产 |
| `aaa_level` | String(10) | 5A / 4A 等 |
| `open_year` | Integer | 开园年份 |
| `establishment_date` | String(20) | 立项日期（当前模型中预留） |
| `official_url` | String(200) | 官网 |
| `description` | Text | 简介 |
| `created_at` / `updated_at` | DateTime | 创建与更新记录 |

### 4.2 `sites`

遗址点表，一个公园可对应多个遗址点。

| 字段 | 类型 | 说明 |
|------|------|------|
| `park_id` | Integer | 外键，关联 `parks.id` |
| `site_name` | String(100) | 遗址点名称 |
| `site_type` | String(50) | 建筑基址 / 墓葬 / 窑址 / 水系等 |
| `period` | String(50) | 所属时期 |
| `discovery_year` | Integer | 发现年份 |
| `excavation_year` | Integer | 发掘年份 |
| `area` | Float | 面积 |
| `integrity_score` | Integer | 完整性评分 |
| `safety_score` | Integer | 安全性评分 |
| `description` | Text | 描述 |
| `coordinates` | Text | GeoJSON 或坐标文本 |

### 4.3 `indicators`

文化效能评估指标表，承载 D1-D27 指标体系。

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | String(10) | 指标编码，唯一 |
| `name` | String(100) | 指标名称 |
| `dimension` | String(50) | 所属维度 |
| `sub_dimension` | String(50) | 子维度 |
| `unit` | String(20) | 单位 |
| `scoring_standard` | Text | 评分标准 |
| `weight_urban` / `weight_suburb` / `weight_rural` | Float | 不同类型公园权重 |
| `data_source` | String(100) | 数据来源 |
| `calculation_method` | Text | 计算方法 |

### 4.4 `scores`

指标评分表，用于保存每个公园在各指标上的评分结果。

| 字段 | 类型 | 说明 |
|------|------|------|
| `park_id` | Integer | 外键，关联 `parks.id` |
| `indicator_id` | Integer | 外键，关联 `indicators.id` |
| `raw_value` | Float | 原始值 |
| `normalized_score` | Integer | 标准化得分，常见值为 20/40/60/80/100 |
| `grade` | String(10) | 等级：好 / 较好 / 一般 / 较差 / 差 |
| `evidence` | Text | 评分依据 |
| `data_year` | Integer | 数据年份 |
| `evaluator` | String(50) | 评估人 |

### 4.5 `surveys` 与 `survey_answers`

问卷部分采用“批次表 + 明细表”的设计。

`surveys` 记录一次调查的总体信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| `park_id` | Integer | 外键，关联 `parks.id` |
| `survey_date` | String(20) | 调查日期 |
| `survey_location` | String(100) | 调查地点 |
| `total_distributed` | Integer | 发放量 |
| `total_collected` | Integer | 回收量 |
| `valid_count` | Integer | 有效问卷数 |
| `valid_rate` | Float | 有效率 |
| `sampling_method` | String(100) | 抽样方法 |

`survey_answers` 记录单个题目的答案：

| 字段 | 类型 | 说明 |
|------|------|------|
| `survey_id` | Integer | 外键，关联 `surveys.id` |
| `respondent_id` | String(20) | 受访者编号 |
| `question_code` | String(20) | 题目编码 |
| `question_text` | Text | 题目内容 |
| `answer_value` | Integer | 1-5 量表值 |
| `answer_text` | Text | 开放式答案 |
| `respondent_age` | String(20) | 年龄段 |
| `respondent_gender` | String(10) | 性别 |
| `respondent_education` | String(20) | 学历 |
| `visit_purpose` | String(50) | 到访目的 |
| `visit_frequency` | String(20) | 到访频次 |
| `transport_mode` | String(20) | 交通方式 |

## 5. 索引与约束

代码中已显式标注或自然形成的常用索引包括：

- `parks.park_type`
- `parks.province`
- `sites.park_id`
- `scores.park_id`
- `scores.indicator_id`
- `surveys.park_id`
- `survey_answers.survey_id`
- `reviews.park_id`
- `reviews.platform`
- `users.username`
- `users.email`

建议继续保持以下约束：

- `indicators.code` 唯一
- `users.username` 唯一
- `users.email` 唯一
- `exhibitions.park_id` 唯一
- `locations.park_id` 唯一

## 7. 当前实现说明

- 当前数据库结构由 ORM 自动创建，表名以代码中的 `__tablename__` 为准
- 现有数据导入与统计逻辑均依赖这些表名和字段名
- 文档中的字段解释应与代码保持同步，后续如果模型改名，文档应同步更新
