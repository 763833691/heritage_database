# 成本与周期估算

## 1. 估算口径

当前仓库已经具备后端、前端、数据库模型、知识图谱脚本和基础问答能力，因此本文件不再把项目当成“从零开始的新建系统”，而是按照“在现有代码基础上完善并可部署”的口径估算。

估算分为两种场景：

- 轻量演示版：以本地开发和课程展示为目标
- 可部署产品版：以 Docker 部署、权限控制、知识图谱和 AI 问答为目标

## 2. 周期估算

### 2.1 轻量演示版

| 阶段 | 工作内容 | 预计工时 | 预计周期 |
|------|----------|----------|----------|
| 文档整理 | README、启动说明、项目方案、数据字典统一 | 12h | 2-3 天 |
| 数据校准 | 初始化数据、样例数据、字段对齐 | 12h | 2-3 天 |
| 页面修补 | 首页、列表页、详情页、聊天页联调 | 24h | 4-5 天 |
| 联调测试 | 基本接口验证、登录、统计、问答 | 12h | 2-3 天 |
| 总计 |  | **60h** | **约 2 周** |

### 2.2 可部署产品版

| 阶段 | 工作内容 | 预计工时 | 预计周期 |
|------|----------|----------|----------|
| 需求收敛 | 明确功能边界、权限、部署方式 | 16h | 3-4 天 |
| 数据治理 | 规范字段、完善导入模板、清洗样例数据 | 32h | 5-7 天 |
| 后端完善 | 接口补齐、异常处理、分页与过滤优化 | 48h | 1-2 周 |
| 前端完善 | 页面视觉、交互细节、图表与地图联动 | 48h | 1-2 周 |
| 图谱与 AI | Neo4j 构建、RAG 链路、问答降级策略 | 40h | 1 周 |
| 部署与验收 | Docker、Nginx、环境变量、验收文档 | 24h | 4-5 天 |
| 总计 |  | **208h** | **约 5-6 周** |

## 3. 成本估算

### 3.1 轻量演示版

| 成本项 | 说明 | 费用 |
|------|------|------|
| 服务器 | 本地电脑或现有笔记本即可 | 0 |
| 数据库 | SQLite 本地文件 | 0 |
| 开发工具 | VS Code、Python、Node.js | 0 |
| AI 调用 | 当前可先不启用外部模型 | 0 |
| 总计 | 适合课程项目和个人演示 | **0 元** |

### 3.2 可部署产品版

| 成本项 | 说明 | 费用区间 |
|------|------|----------|
| 云服务器 | 2 核 4G 起步，适合演示与小流量访问 | 1,000 - 3,000 元/年 |
| 域名 | 普通 .com 域名 | 50 - 100 元/年 |
| SSL | Let’s Encrypt 免费证书 | 0 |
| PostgreSQL | 自建或云数据库 | 0 - 1,500 元/年 |
| Neo4j | 本地自建或云托管 | 0 - 2,000 元/年 |
| AI 调用 | 视是否接入外部大模型而定 | 0 - 1,000 元/年 |
| 总计 |  | **约 1,050 - 7,600 元/年** |

## 4. 人力配置建议

### 4.1 轻量演示版

- 1 名熟悉 Python 的研究生
- 1 名熟悉前端的协作者可选

### 4.2 可部署产品版

- 1 名后端开发
- 1 名前端开发
- 1 名数据/图谱整理人员
- 1 名项目协调或需求整理人员

## 5. 风险与缓冲

| 风险项 | 影响 | 说明 |
|------|------|------|
| 数据口径不统一 | 中 | 需要先统一字段、编码和评分规则 |
| 图谱构建缺失数据 | 中 | Neo4j 依赖结构化数据完整性 |
| 外部 AI 不可用 | 中 | 需保留本地规则式回答降级方案 |
| 部署环境差异 | 中 | Docker 配置和本地配置需分离说明 |
| 后期返工 | 中 | 文档、代码、模板必须同步维护 |

## 6. 当前仓库的现实判断

从代码状态看，项目已经不是“完全空白”的原型，而是“功能骨架已具备、等待文档整理和产品化收口”的阶段。因此最合理的推进顺序是：

1. 先统一文档与启动方式
2. 再修补页面和接口体验
3. 最后做部署、验收与演示优化
