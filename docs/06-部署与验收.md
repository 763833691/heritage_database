# 部署与验收

## 1. 目标

本文档用于描述项目从“代码可运行”到“可验收交付”的最后一公里，重点回答三个问题：

- 如何部署
- 如何验证
- 出问题时先看哪里

## 2. 部署方式

### 2.1 Docker Compose

适合统一环境和演示交付。

```bash
docker compose up -d postgres neo4j
docker compose run --rm backend python scripts/init_db.py
docker compose run --rm backend python scripts/build_kg.py
docker compose up -d
```

说明：

- `build_kg.py` 依赖 Neo4j，请先设置 `NEO4J_ENABLED=true`
- 如果暂时不需要知识图谱，可以跳过构图步骤

### 2.2 本地开发

适合联调和功能开发。

```bash
docker compose up -d postgres neo4j

cd backend
pip install -r requirements.txt
python scripts/init_db.py
uvicorn app.main:app --reload --port 8000

cd ../frontend
npm install
npm run dev
```

## 3. 推荐启动顺序

1. 启动数据库服务
2. 初始化数据表和示例数据
3. 启动后端 API
4. 启动前端页面
5. 如需图谱，最后构建 Neo4j 数据

## 4. 环境变量检查

建议在 `.env` 或运行环境中至少确认以下变量：

```bash
DB_TYPE=postgres
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_USER=heritage
POSTGRES_PASSWORD=heritage123
POSTGRES_DB=heritage_db

NEO4J_ENABLED=true
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=heritage123
```

如果暂时只想本地跑 SQLite，可以保持：

```bash
DB_TYPE=sqlite
```

## 5. 验收清单

### 5.1 基础验收

- 能打开 `http://localhost:8000/health`
- 能打开 `http://localhost:8000/docs`
- 前端页面可以访问
- 使用 `admin/admin123` 成功登录

### 5.2 数据验收

- 数据总览页能显示公园、遗址点和指标数量
- 遗址公园列表页可按类型、省份、批次筛选
- 公园详情页可看到评分信息

### 5.3 图谱验收

- `scripts/build_kg.py` 可成功执行
- `GET /api/kg/stats` 有返回
- `GET /api/kg/search` 可检索公园或指标

### 5.4 AI 验收

- 聊天页可发送问题
- 对比类问题能返回雷达图数据或至少返回可解释结果
- 无外部大模型时，系统仍能返回本地模板式答案

## 6. 回归检查点

建议每次改完后重点确认：

- 登录是否还能正常拿到 JWT
- `/api/statistics/overview` 是否还能返回统计数据
- `/api/kg/*` 在 Neo4j 开启和关闭两种模式下是否都可用
- `/api/chat` 是否仍能返回 `message`、`sources` 和 `chart_data`

## 7. 常见问题

### 7.1 启动后无法登录

优先检查：

1. 是否执行了 `init_db.py`
2. `admin/admin123` 是否被创建
3. 数据库连接是否正确

### 7.2 图谱脚本报错

优先检查：

1. `NEO4J_ENABLED=true` 是否生效
2. Neo4j 容器是否已经启动
3. `NEO4J_PASSWORD` 是否与容器一致

### 7.3 前端白屏或请求失败

优先检查：

1. 后端是否在 `8000` 端口运行
2. 前端代理或 `baseURL` 是否指向 `/api`
3. 浏览器控制台是否有 401/403/500
