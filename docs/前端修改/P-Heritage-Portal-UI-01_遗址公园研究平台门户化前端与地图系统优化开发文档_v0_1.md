# P-Heritage-Portal-UI-01 遗址公园研究平台门户化前端与地图系统优化开发文档 v0.1

> 文档类型：前端重构 / 门户化改造 / 地图技术升级 / 可执行开发文档  
> 适用项目：遗址公园研究平台  
> 执行对象：Codex / AI IDE Agent  
> 文档版本：v0.1  
> 目标阶段：前端门户化第二版  
> 核心要求：**取消所有页面的全局左侧导航栏，统一为顶部门户导航；替换当前默认地图视觉与交互；保留现有真实业务能力、真实接口和真实数据。**

---

## 0. 一句话结论

本阶段不是简单“换皮”，而是把当前偏后台控制台的遗址公园研究平台，重构为：

```text
门户型研究平台
= 统一顶部导航
+ 首页内容门户
+ 专题数据页面
+ 现代地图浏览
+ 知识与文献研究工具
+ AI 辅助研究入口
+ 轻量化数据管理
```

前台所有页面不得再出现全局左侧导航栏。

地图正式落地采用：

```text
高德地图 JavaScript API 2.0
+ 自定义地图样式
+ Loca 2.0 数据可视化图层
+ 自研 MapProviderAdapter 适配层
```

同时预留未来接入：

```text
MapLibre GL JS
+ PMTiles / 自建矢量瓦片
+ deck.gl
```

当前阶段不直接引入第二套地图运行时，不增加不必要的复杂度。

# 1. 背景与现有问题

## 1.1 当前页面仍然是后台控制台结构

现有页面主要表现为：

```text
固定深色左侧导航
+ 顶部标题栏
+ 大面积白色后台卡片
+ 表格 / 图表 / 地图工具
```

这种结构适合内部 Admin Console，但不适合面向研究人员、管理机构、游客或合作单位展示的门户网站。

主要问题：

1. 页面缺少统一主题和品牌识别；
2. 首页没有形成“平台价值—核心入口—研究内容—数据能力”的内容叙事；
3. 多个页面仍然保留左侧导航，和门户型定位冲突；
4. 页面之间像多个后台功能拼接，缺少整体感；
5. 空白区域、空图表、加载状态过多；
6. `Not authenticated` 提示重复出现，严重破坏体验；
7. 当前地图使用默认底图和默认控件，视觉偏传统 GIS 工具；
8. 地图点位缺少聚合、层级、选中反馈和内容详情联动；
9. 前台与数据管理功能没有形成清晰但统一的产品结构。

---

## 1.2 本阶段要解决的核心问题

```text
问题一：所有页面统一为门户型顶部导航，不保留全局左侧栏。
问题二：地图从“默认地图组件”升级为“遗址研究专题地图”。
问题三：页面内容从后台卡片堆叠升级为研究门户信息架构。
问题四：保留现有 API、数据和功能，不因 UI 重构破坏业务。
问题五：清理重复鉴权提示、空状态和加载状态。
```

# 2. 本阶段目标

## 2.1 产品目标

完成一套统一、专业、具有遗址公园主题性的门户型研究平台前端。

目标关键词：

```text
专业
克制
清晰
可信
现代
文化遗产主题
研究平台属性
数据可视化能力
```

不追求：

```text

大量玻璃拟态
全屏霓虹动画
复杂 3D 堆叠
娱乐化视觉
传统后台模板感
```

---

1. 删除全部页面的全局左侧导航栏；

4. 首页改造成完整门户首页；

12. 知识库页取消全局侧栏；

17. 完成桌面端与移动端响应式；

# 3. 非目标与禁止事项

## 3.1 本阶段非目标

本阶段不要求：

1. 重写后端业务逻辑；
2. 重建数据库；
3. 更换现有登录系统；
4. 重建知识图谱后端；
5. 重建 AI 助手模型调用链；
6. 重建文献计量算法；
7. 重建评价指标体系；
8. 增加新的虚假统计数据；
9. 为了展示效果创建 Mock API；
10. 一次性建设完整 3D 地理信息平台。

---

## 3.2 禁止事项

### 禁止 1：保留任何全局左侧导航栏

包括但不限于：

```text
数据总览
遗址公园
地图浏览
对比分析
知识图谱
AI 助手
知识库
文献计量
数据管理
```

这些入口必须统一放到顶部主导航中。

允许出现的左侧区域只有：

```text
地图页面的局部筛选面板
AI 助手页面内部的会话列表
知识库页面内部的分类筛选
```

这些属于页面内容，不属于全局导航。

---

### 禁止 2：Mock 冒充真实数据

```text
正式页面只能使用真实 API、真实数据库或当前已有真实静态配置。
接口未接入时必须显示“暂未接入”或明确错误。
不得用随机数、硬编码成功结果或示例数据冒充生产数据。
```

未实现能力应返回或展示：

```text
401 AUTH_REQUIRED
403 FORBIDDEN
404 NOT_FOUND
501 NOT_IMPLEMENTED
503 SERVICE_UNAVAILABLE
```

---

### 禁止 3：破坏已有路由和功能

重构必须优先保持：

```text
现有业务路由可访问
现有接口调用继续工作
现有筛选条件继续可用
现有查询参数尽量兼容
现有登录态继续可用
现有数据管理操作继续可用
```

如必须修改路由，必须添加兼容重定向。

---

### 禁止 4：隐藏地图版权与服务标识

不得通过 CSS 或 DOM 修改方式隐藏地图服务商要求展示的 Logo、审图号、版权或归属信息。

---

### 禁止 5：一次性同时接入两套地图运行时

当前正式运行只实现：

```text
AMapProvider
```

只建立 MapProviderAdapter 接口，为未来 MapLibre 预留结构。

不得在当前页面同时初始化 AMap 与 MapLibre。

# 7. 统一视觉系统

## 7.1 色彩

品牌主色：

```css
--brand-600: #2563EB;
--brand-500: #3B82F6;
--brand-100: #DBEAFE;
```

主题辅助色：

```css
--violet-500: #7C3AED;
--cyan-500: #06B6D4;
--green-500: #22C55E;
--orange-500: #F59E0B;
```

中性色：

```css
--text-primary: #172033;
--text-secondary: #667085;
--text-tertiary: #98A2B3;
--border: #E7EAF0;
--surface: #FFFFFF;
--surface-soft: #F7F9FC;
--page-bg: #F5F7FB;
```

禁止：

```text
各页面自行定义完全不同的蓝色
大量高饱和渐变
彩虹式地图点位
深色侧栏残留
```

---

## 7.2 字体和层级

优先使用系统中文字体栈：

```css
font-family:
  Inter,
  "SF Pro Display",
  "PingFang SC",
  "Microsoft YaHei",
  system-ui,
  sans-serif;
```

建议层级：

```text
首页主标题：48～64px
页面主标题：34～44px
模块标题：20～24px
卡片标题：16～18px
正文：14～16px
辅助信息：12～14px
```

移动端按比例缩小。

---

## 7.3 圆角和阴影

```text
大区块圆角：20px
普通卡片圆角：14px～16px
按钮圆角：10px～12px
胶囊标签圆角：999px
```

阴影必须克制：

```css
box-shadow: 0 8px 30px rgba(31, 45, 61, 0.06);
```

不要使用大面积强发光阴影。

---

## 7.4 页面宽度

```text
首页 Hero：可全宽背景，内容限制在 1440px
普通页面内容：最大 1440px
阅读类内容：最大 1180px
AI 助手：可使用 1500px
地图页面：允许接近全宽
```

# 8.5 地图浏览页

地图页是本轮重点。

页面不得再沿用传统 Leaflet 默认地图 + 默认标记 + 默认控件的视觉。

## 页面布局

```text
顶部：统一 PortalHeader
页面标题区：标题、简介、分享、导出
主体：
  左侧：页面内部筛选面板
  中间：地图画布
  右侧：选中公园详情面板
底部：统计概览条
```

左侧筛选面板不是全局导航，面板支持折叠。

## 左侧筛选内容

```text
公园类型
所属区域
批次
保护级别
指标类别
指标范围
清空筛选
应用筛选
```

## 右侧详情内容

```text
封面图
公园名称
省市
批次
类型
核心指标
一句话简介
进入详情页
加入对比
收藏
```

## 地图视觉要求

```text
浅色低干扰底图
弱化道路和普通 POI
突出省界和城市层级
遗址点使用统一蓝紫色体系
选中点使用外环与轻微脉冲
聚合点显示数量
不同数量级使用大小变化，不使用高饱和彩虹色
```

## 地图层级行为

全国视图：

```text

```

省域视图：

```text

```

城市 / 公园视图：

```text

展示公园名称
```


## 20.2 地图回滚

地图必须通过 Provider Adapter 解耦。

如新地图 SDK 因 Key 或部署配置不可用，可回滚到前一版本代码，但不得在生产代码中静默切换到虚假地图。

错误状态应显示：

```text
地图服务暂不可用
请检查地图服务配置
```

# 21. Codex 执行要求

将本文件交给 Codex 后，执行指令如下：

```text
请严格按照本开发文档直接完成遗址公园研究平台前端门户化与地图系统优化。

执行要求：

1. 先只读审计仓库并生成代码事实对齐报告，但不要停在审计阶段，完成审计后立即继续开发。
2. 删除所有目标页面的全局左侧导航栏，统一为顶部 PortalHeader。
3. 数据管理页也不得保留全局左侧导航，使用页面内部顶部 Tabs。
4. 保留现有真实 API、真实数据、真实登录与业务操作。
5. 禁止使用 Mock、随机数或硬编码成功结果冒充真实功能。
6. 当前生产地图采用高德地图 JavaScript API 2.0 + 自定义样式 + Loca 2.0。
7. 建立 MapProviderAdapter，当前只实现 AMapProvider，预留未来 MapLibreProvider。
8. 地图 Key 必须走环境变量，不得写死，不得隐藏地图版权信息。
9. 修复重复 Not authenticated Toast，统一处理 401 / 403。
10. 复用当前技术栈、目录、组件、请求层和图表库，不得重复建立第二套前端架构。
11. 完成后执行 Lint、Typecheck、测试、生产构建和关键页面 E2E。
12. 生成桌面端和移动端验收截图。
13. 生成 Acceptance Report。
14. 不要只输出方案，直接修改代码并完成验收。
15. 未经明确要求，不要 commit，不要 push。
```
